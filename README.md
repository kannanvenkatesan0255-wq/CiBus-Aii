## 1. Project Overview
**CIBUS-AI** is a college Machine Learning Project-Based Learning (PBL) system engineered to forecast the quantity of edible surplus meals generated by commercial food establishments (cafeterias, banquet halls, restaurants, and caterers) *before* final food consumption and sales take place.

By transforming surplus estimation from a reactive end-of-day scramble into a proactive pre-service predictive alert, CIBUS-AI provides the foundational intelligence necessary to coordinate timely food recovery and redistribution to local NGOs and community shelters.

---

## 2. Problem Statement
Commercial dining facilities and event caterers face unpredictable attendance and customer turnout driven by weather shocks, calendar anomalies, and service formats. Consequently, vast quantities of wholesome food are prepared as buffer portions and discarded at the conclusion of service cycles.

Redistribution charities typically receive notifications only after kitchens close, leaving an impractical operational window to inspect, package, transport, and distribute food before it spoils. Advance foresight is critical to make surplus redistribution viable.

---

## 3. Driving Question
> *"How can pre-service operational indicators, environmental factors, and advance footfall forecasts be modeled using Supervised Machine Learning Regression to accurately predict food surplus volume before service conclusion, without incurring data leakage?"*

---

## 4. Project Objectives
- **Technical Objective:** Formulate and deploy a leak-free regression pipeline in Python using `scikit-learn` to forecast surplus meal counts.
- **Machine Learning Objective:** Design, train, tune, and evaluate an ensemble `RandomForestRegressor` against an empirical baseline, analyzing residual behaviors and Mean Decrease in Impurity (MDI) feature importances.
- **PBL Learning Objective:** Master the end-to-end ML lifecycle: data synthesis, leakage-safe transformation, cross-validated tuning, model serialization (`joblib`), and defensible evaluation reporting.

## 6. Machine Learning Problem Formulation
- **Learning Paradigm:** Supervised Learning
- **Task Type:** Continuous Regression
- **Target Variable ($y$):** `Surplus_Meals` (Non-negative count of leftover edible meals)
- **Primary Algorithm:** Random Forest Regressor (`sklearn.ensemble.RandomForestRegressor`)

---

## 7. Dataset Description

- **Location:** `ai-engine/dataset/food_surplus.csv`
- **Total Records ($N$):** Exactly 8,000 rows, 10 columns (0 missing values, 0 duplicate records).
- **Random Seed:** `42` (ensures 100% deterministic reproducibility).

### Input Features ($X \in \mathbb{R}^9$):
1. `Day` *(Categorical)*: Day of the week (`Monday` – `Sunday`).
2. `Weather` *(Categorical)*: Environmental condition (`Sunny`, `Cloudy`, `Rainy`, `Stormy`).
3. `Customers_Forecast` *(Numeric Integer)*: Planned diner count based on bookings ($60 - 950$).
4. `Meals_Prepared` *(Numeric Integer)*: Total meal portions batch-cooked in kitchen ($84 - 1,360$).
5. `Festival` *(Categorical)*: Festive marker (`No`, `Diwali`, `Eid`, `Christmas`, `New Year`).
6. `Event_Type` *(Categorical)*: Service format (`Regular`, `Buffet`, `Corporate`, `Banquet`).
7. `Staff_Count` *(Numeric Integer)*: Kitchen and floor staff on duty ($5 - 48$).
8. `Avg_Rating` *(Numeric Float)*: Quality satisfaction score ($2.51 - 5.00$).
9. `Special_Event` *(Binary 0/1)*: High-profile or unscheduled occasion flag.

### Target ($y$):
10. `Surplus_Meals` *(Numeric Float)*: Physical count of edible meals unconsumed post-service ($0.0 - 686.0$, Mean = $118.59$, Std = $97.27$).

---

## 8. Data Leakage Prevention: The `Meals_Sold` Exclusion Rule

In post-service accounting:
$$\text{Surplus\_Meals} = \text{Meals\_Prepared} - \text{Meals\_Sold}$$

**Why `Meals_Sold` is strictly excluded from all features and inference:**
1. **Target Leakage:** Including `Meals_Sold` reduces the machine learning problem to trivial arithmetic subtraction, preventing the model from discovering real behavioral interactions.
2. **Temporal Invalidity:** `Meals_Sold` is only known **after** service closure. A model requiring `Meals_Sold` cannot make pre-service advance predictions needed to coordinate timely NGO food recovery.

## 9. Machine Learning Pipeline Architecture

```
Raw Data Generation (8000 x 10)
              │
              ▼
Leakage-Safe Preprocessing & Validation
              │
              ▼
80/20 Train-Test Split (random_state=42)
  ├── Training Set (6400 x 25) ──► Fit Preprocessor ONLY on X_train
  └── Test Set     (1600 x 25) ──► Transform X_test (Zero snooping)
              │
              ▼
Iteration 1: Baseline Random Forest (n=100, default params)
              │
              ▼
Iteration 2: 3-Fold Cross-Validated Hyperparameter Refinement
              │
              ▼
Final Model Selection & Serialization (food_surplus_model.pkl)
              │
              ▼
Test Set Evaluation (MAE: 14.58 meals, RMSE: 20.69 meals, R²: 0.9543)
              │
              ▼
Feature Importance Analysis (MDI) & Standalone Prediction Engine (predict.py)
```

## 10. Actual Experimental Results

### Baseline vs. Refined Final Model Comparison ($N=1,600$ Test Set):
| Metric | Baseline Model | Refined Final Model | Absolute Delta ($\Delta$) | Analysis |
| :--- | :---: | :---: | :---: | :--- |
| **MAE** | `14.2939 meals` | **`14.5793 meals`** | $+0.2854$ meals | Highly comparable ($\approx 14.4$ meals average error). |
| **RMSE** | `20.5429 meals` | **`20.6869 meals`** | $+0.1440$ meals | Highly comparable residual variance. |
| **$R^2$ Score** | `0.9549` | **`0.9543`** | $-0.0006$ | Both models explain $>95.4\%$ variance. |

> **Critical Note:** $R^2$ is the **Coefficient of Determination** (explained variance). It is strictly distinct from classification accuracy.

## 13. Backend REST API Integration Layer

CIBUS-AI provides an asynchronous RESTful backend service built on **FastAPI** and **Uvicorn** to expose the trained Random Forest engine for web and mobile client integration.

### Data Flow:
$$\text{Client (HTTP JSON)} \longrightarrow \text{FastAPI Route} \longrightarrow \text{Pydantic Schema Validation} \longrightarrow \text{Prediction Service} \longrightarrow \text{Trained Model} \longrightarrow \text{Surplus Forecast JSON}$$

### Key Endpoints:
- `GET /health` – Confirms server responsiveness and verifies ML model & preprocessor loading.
- `GET /api/model-info` – Returns active model metadata, feature schemas, and evaluation metrics.
- `POST /api/predict` – Accepts operational features (e.g. `Day`, `Weather`, `Meals_Prepared`) and returns predicted surplus with logistical advice.
- `GET /docs` – Interactive Swagger UI API explorer.

## 15. Installation & Reproduction Guide

### 1. Environment Setup
```bash
# Clone the repository
git clone https://github.com/kannanvenkatesan0255-wq/CiBus-Aii.git
cd CiBus-Aii

# Install required ML & backend dependencies
pip install -r ai-engine/requirements.txt
pip install -r backend/requirements.txt
```

### 2. Step-by-Step ML Pipeline Execution
```bash
# 1. Generate and validate the 8,000-record dataset
python -u ai-engine/dataset/generate_dataset.py
python -u ai-engine/dataset/validate_dataset.py

# 2. Run data preprocessing & encoding pipeline
python -u ai-engine/preprocessing/preprocess.py

# 3. Train the baseline Random Forest model
python -u ai-engine/training/train_baseline.py

# 4. Perform cross-validated hyperparameter tuning & train final model
python -u ai-engine/training/train_model.py

# 5. Extract feature importances and generate diagnostic charts
python -u ai-engine/training/feature_importance.py

# 6. Evaluate the final model on held-out test set
python -u ai-engine/evaluation/evaluate_model.py

# 7. Run automated ML prediction test suite (9 unit tests)
python -u -m unittest ai-engine/prediction/test_predict.py
```

### 3. Backend API Execution & Testing
```bash
# Start FastAPI backend development server
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

# Run automated backend API test suite (10 tests)
python -u -m unittest backend/tests/test_prediction_api.py

# Run interactive prediction CLI demo
python -u ai-engine/prediction/predict.py --day Saturday --weather Sunny --customers 350 --meals 400 --event Regular --rating 4.3
```

## 15. Limitations
- **Synthetic Behavioral Data:** Evaluated on synthetic operational records; real-world catering establishments exhibit micro-climate and seasonal variability not fully modeled.
- **Static Pre-Service Window:** Forecasts apply prior to food preparation and do not stream dynamic intra-shift kitchen replenishment.
- **No Logistics Integration Yet:** Downstream NGO pairing, vehicle routing, and web UI are scheduled for subsequent project milestones.
